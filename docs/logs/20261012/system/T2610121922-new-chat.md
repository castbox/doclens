# 顶部新建独立聊天

## 变更与范围

按用户确认的“独立空白聊天”实现，在 `/docs` 顶部“展开目录 / 收起目录”左侧加入“新建聊天”。无需先选择文档，每次新建获得新的会话 ID，打开空白全屏聊天；输入框自动聚焦，支持发送、流式回答、停止和重试。创建期间禁用按钮并防止重复点击，失败时显示可读提示。

界面复用现有聊天组件，根据文档 / 独立会话区分标题、输入提示与历史上下文。顶部按钮保持既有 MUI 样式，触控高度 44px；窄屏导航自然换行，目录及审阅面板按实际导航栏高度定位。已先同步 PRD FR-16，再实现代码，并补齐 README 接口与冒烟步骤。

新增 `POST /api/chat/conversations` 返回 201 与空聊天历史；历史及流式接口支持互斥的 `path` / `conversationId`。独立模式只允许发送及重试，创建和读取不调用模型，也不要求模型密钥。问题会发送到 DeepSeek 的提示在输入区下方可见。

## Parallel Specialists Multi-agents

本次实际执行三个互不重叠的专业任务：

- `chat_ui`：工作区导航、聊天 Dialog、hook 与输入框，以及导航换行后的 Drawer 定位。
- `chat_backend`：会话类型、输入验证、客户端服务、API、SQLite schema / migration 和服务回归。
- `chat_validation`：独立只读审查、生产构建的浏览器验收与证据保存。
- 主线程：PRD / README、实现整合、完整测试与构建、源文件哈希核对、截图人工复核及 Git 收尾。

## 行为保护与存储

复用既有测试保护文档路径安全、完整上下文、历史分页、租约、中断与重试，再将存储操作按固定的文档 / 独立聊天表分流，共用原流式引擎。原文档模式的路径入口、空历史概述和历史恢复继续通过回归。

独立聊天新增 `standalone_chat_conversations` 与 `standalone_chat_messages`，使用 canonical docs root 与随机会话 ID 隔离；文档路径字段为空。建表为兼容增量，原文档聊天唯一索引与已有审阅、已读、星标记录保留。运行时按需确保新表，也纳入 `pnpm db:migrate`。所有聊天数据写入 `DOCLENS_DB_PATH`，文档源只读。

独立聊天目前提供新建入口；尚未新增历史列表。旧独立会话不会被新建覆盖，历史仍可按会话 ID 通过接口读取。

## 验收边界与回滚

浏览器使用自建文档根、独立临时 SQLite 和生产构建，模型上游仅绑定 `127.0.0.1` 的模拟 SSE 服务。没有复制本地 `.env` 或调用收费模型；验证的是创建、会话隔离、持久化和交互传输，真实 DeepSeek 回答质量未纳入本次验收。

验收完成后已停止本次创建的两个临时服务；MCP 自动生成的浏览器快照移出仓库并保留在本次临时目录，正式证据按本简报前缀保存。提交前再次检查 AppleDouble、源文件哈希及 diff 均通过。

回滚可 revert 本次提交；新增聊天表可留存，无需删除历史或修改已有表。任务开始的 `main` 已领先远端 5 个提交，本次只提交自身变更；原有未跟踪 `test.zip` 保留。
