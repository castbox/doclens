# 聊天 Mermaid 高度限制修复

## 问题与改动

原有聊天图表将 SVG 宽度强制设为消息区的 100%，竖向图会被等比例放大，缺少高度上限，容易占满聊天区域。

- 聊天内嵌图表区域与 SVG 均限制为 `calc(100dvh / 3)`，最高占当前页面高度的 1/3。
- SVG 使用自动宽高，同时受内容宽度约束，保持比例完整缩小，不裁切节点，也不强制放大小图。窗口尺寸变化时通过 CSS 自动重新适配。
- 渲染等待区域同样受高度限制；图表错误后的源码回退区域可在限高区域内滚动。
- 保留无外框、无标题栏和右上角 44×44px 放大按钮；小图区域提供按钮所需空间，高度仍服从 1/3 上限。
- 放大预览继续按自然尺寸显示并支持平移；普通文档预览的样式保持原有行为。

影响文件为 `src/features/docs/ui/MermaidCodeBlock.tsx`，未调整聊天 API、数据库或文档读取逻辑。已同步 [PRD FR-14 / 验收项 17](../../../prd/doclens_prd.md) 和 [README](../../../../README.md)。

| --- | ---: | ---: | ---: | ---: |
| 桌面 1440×900 | 300px | 300px | 69.53px | 70px |
| 手机竖屏 375×812 | 270.67px | 270.66px | 52px | 70px |
| 手机横屏 812×375 | 125px | 125px | 52px | 70px |

9 组实际浏览器检查全部通过：图表及区域均未超出高度上限，SVG 比例保持、节点完整、图表不裁切、聊天区无横向溢出，右上角按钮保持 44×44px。横向图的 52px 区域包含按钮所需空间，图表本身按宽度进一步缩小。[完整尺寸记录](T2610121801-mermaid-height-browser.json)。

- 同一图表从 900px 高窗口切换为 600px 高窗口后，区域和 SVG 自动变为 200px；图表 ID 保持一致，未重新生成回答。
- 手机放大预览恢复 SVG 的 140×798px 自然尺寸，`max-height: none`，可在 752px 高的容器内纵向平移。
- 普通文档预览保留 Mermaid 标题栏及自然高度 798px，未应用聊天高度上限。

- `pnpm test:run`：23 个测试文件、180 项测试全部通过。[测试输出](T2610121801-mermaid-height-tests.txt)。
- 根工作区 `pnpm build`：编译、类型校验和构建通过。[构建输出](T2610121801-mermaid-height-build.txt)。保留既有文档根目录不存在的 watcher 警告，未改动本地业务配置。

- 本机 Node 与 better-sqlite3 原生模块均为 arm64，未重装依赖。

## 影响与回滚

本次只修改聊天 Mermaid 的内嵌尺寸。高图缩小后文字可能偏小，可点击右上角放大按钮阅读细节；历史、上下文、流式请求和普通文档图表不受影响。回滚可 revert 本次 fix commit，无数据迁移或删除。原有未跟踪 `test.zip` 保留；本地密钥未写入代码或验收产物。
