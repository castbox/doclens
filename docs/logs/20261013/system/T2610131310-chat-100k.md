# 聊天输入上限提高至 100K 字符

## 结果与范围

原输入上限为 4,000 字符，用户输入 4,768 字符时会提示“超出 768 个字符”。本次将文档与独立聊天的单条输入上限统一提高到 100,000 字符；计数、发送按钮、hook、API 和历史回包校验共同使用新上限。100,000 字符可提交，100,001 字符明确拦截。

历史协议按角色区分：用户消息可保存和读取 100K，助手回复继续遵守原 32K 上限。JSON 请求体与历史读取的字节上限提高至 1 MiB，容纳控制字符转义后约 600KB 的合法 100K 输入。SSE 保持逐事件解析，合法多帧合计超过 1 MiB 仍可读取。

当前问题完整传给模型，旧对话超预算时才从本轮上下文排除。模型历史与历史分页仍各为 40 条 / 100K 字符；100K 用户消息与回复超过一页时，可按已有消息 ID 加载更早记录，数据库原文完整保存。SQLite 的 TEXT 字段无需 schema 或数据迁移，docs 源文件读取规则保持。

## 边界与回滚

使用临时文档根和 SQLite，本地模拟服务只记录输入长度、SHA-256、请求字节数及角色长度，不保存输入正文；没有读取本地凭证或调用付费模型。上游真实生成质量未纳入本次验收。

回退应用输入上限时应保留读取 100K 用户历史的兼容逻辑：旧客户端的 32K 通用消息校验会拒绝本次新增的长记录。历史无需删除，也无需数据库迁移。原有未跟踪 `test.zip` 保留。
